# STT controls checked against current primary docs

Checked 2026-10-25. Only final-menu vocabulary and finite valid answer strings are sent as recognition hints. No caller names, numbers, instructions or prices.

- Keyterms are plain strings; use repeated `keyterm` query parameters. Each multi-word phrase stays in one encoded value, such as `chicken karahi`, `garlic naan` or `seekh kabab`. Weights, comma-separated lists and legacy `keywords` syntax do not apply. The limit is 500 provider tokens. The implementation uses a conservative 450 UTF-8-byte budget (including a byte per term), not an invented provider-token count. Sending all repeated full menu names previously exceeded the live limit. [Keyterms](https://developers.deepgram.com/docs/keyterm).
- Nova-3 and Flux both support replacing mid-stream hints with `{"type":"Configure","keyterms":[...]}`. Empty arrays clear hints. Configuration failure retains the preceding list; it is not treated as a fatal transcription error. The implementation boosts size, spice, candidate or cart-name answers after the engine asks a question. Eighteen configuration updates in the paired pause experiment were acknowledged successfully. [Streaming API](https://developers.deepgram.com/reference/speech-to-text/listen-streaming).
- Browser variants are Flux `flux-general-en` on `/v2/listen`, Nova-3 `language=multi`, and Nova-3 `language=en-IN` on `/v1/listen`. `en-IN` is documented and authenticated successfully in live tests. They share the same compact keyterms and PCM format. No winner is selected. [Models/languages](https://developers.deepgram.com/docs/models-languages-overview).
- Flux's `eager_eot_threshold` enables EagerEndOfTurn and TurnResumed; EndOfTurn is authoritative. If a caller resumes, any speculative draft must be discarded. Engine speculation has been removed because engine work is small and it adds cancellation complexity. No eager event runs the engine or TTS here. [Flux eager events](https://developers.deepgram.com/docs/flux/voice-agent-eager-eot).
- The current streaming schema returns `channel.alternatives[]`, but does not document an N-best request control for Nova-3/Flux. We therefore do not assume multiple hypotheses, send an undocumented alternatives setting or choose dishes from hypothetical alternates. This experiment does not establish N-best support; an array's name is not evidence of multiple hypotheses. [Streaming reference](https://developers.deepgram.com/reference/speech-to-text/listen-streaming).

The same thirty public script utterances were synthesized ONCE in RAM, then broadcast to the three STT variants. This is a controlled synthetic transcription diagnostic with three simultaneous streams, not a production latency benchmark or evidence of Pakistani/Indian accent accuracy. Latin-script Urdu/Hindi rendered by an English TTS voice is particularly unrepresentative. Exact normalized-text agreement also penalizes benign digit/script/spelling differences. Missing/late finals and all raw synthetic transcripts are retained in `eval/results/voice-stt-30.json`. No audio file is saved.

The latest paired experiment verifies **56 actual URL keyterm values** on each configuration (logging counts only). Removing just `garlic naan` leaves 55; both arms get identical PCM. Of six synthetic inputs per configuration, Flux recognizes the exact phrase 1→2 times, en-IN 6→6. Nova multilingual gives 4→6, with one control connection failure; on the five pairs with both connections working it is 4→5. These small synthetic counts do not establish a boost for a human accent.
